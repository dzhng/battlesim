# Final choices

The user’s scope and interaction choices are retained in the [exploration map](visualizations/decisions.html). This ledger records the architectural decisions made within that scope. All entries describe the final code. Review the medium-confidence bounds first: they are deliberately conservative and can be revised with evidence.

## Sound — medium confidence

### Ordinary Play allows at most two generated candidates within eight seconds

When: player admission pass. Pressing Play first tries a fresh seed with the selected type and size. A seed-dependent refusal can try another; exhausting the attempt or time allowance moves to the released Market Town assault. The alternative is either immediate fallback or a longer search that consumes startup time. The eight seconds cover candidate preparation, not drawing the final view.

Gap: the user required a playable battle without choosing retry numbers. Reach: future changes must preserve enough time to resolve and draw the fallback. Verdict: sound; selection is finite and the actual winner becomes the URL and replay identity. Confidence: medium.

### Advanced numerical controls have conservative domains

When: policy extraction and native report passes. Newly extracted placement/search counts have a positive domain capped at 4096; existing count controls retain their owner’s validation. Newly extracted sampling steps and morphology distances remain finite and positive; stored sine/cosine thresholds retain their meaningful domains. This exposes tuning without treating every number as an unrestricted input. Supporting zero for additional cosmetic reach settings would require checking their readers first.

Gap: there was no agreed legal domain for the newly exposed constants. Reach: these bounds constrain extreme experiments; they are safeguards, not measured performance guarantees. Verdict: sound; defaults remain exact and correctness is not bypassed. Confidence: medium.

### Analysis rejects excessive sampling without thinning it

When: native report pass. An edited sight spacing whose conservative grid forecast exceeds one million positions returns an unavailable report. The tool preserves the requested spacing instead of silently substituting fewer samples. Native jobs also have finite process-time and output bounds, independent of map admission.

Gap: edited analysis workload needed a finite boundary. Reach: a larger analysis envelope needs a deliberate capacity decision; a report must never claim the requested quality after reducing it invisibly. Verdict: sound; refusals are explicit and no sampling claim changes. Confidence: medium.

### A completed sample outcome survives an interrupted source export

When: final editor review. If a seed finishes and the user cancels while its input receipt is being exported, the sample keeps that result and marks the missing receipt. Identical source bundles are stored once, with each row naming its bundle. Waiting to expose a result until export finished would hide completed work; repeating all source text per row would inflate the export.

Gap: cancellation during receipt capture was unspecified. Reach: complete outcomes and complete source export remain separate claims. Execution failures have no tested-input fingerprint or receipt; they explicitly say that evidence is unavailable. Verdict: sound; incomplete evidence is visible instead of appearing reproducible. Confidence: medium.

### Unknown worker faults go directly to the saved fallback

When: player admission pass. If the worker fails for an unknown runtime reason, Play attempts the independently resolved released battlefield once. Only recognized generation or placement exhaustion tries another generated seed. Repeating an unknown fault is unlikely to improve it and spends the allowance.

Gap: the user required recovery without prescribing fault classification. Reach: new retryable diagnostics must represent something a fresh map seed can change. Verdict: sound; attempts retain their failures for developer inspection. Confidence: medium.

## Sound — high confidence

### Developer reports use native Rust without expanding production Wasm APIs

When: spec and native report passes. A local draft is sent to a cancellable native process that calls the existing generator, compiler, inspector and simulation analysis. The browser receives the result and exact-input receipt. A new developer-only Wasm session API would create another retained world and output protocol in gameplay.

Gap: the workbench needed access to native inspection and analysis. Reach: local tuning requires the native developer executable; production preparation keeps its existing boundary. Verdict: sound; the existing Rust owners remain authoritative. Confidence: high.

### Released-map admission stays independent of generation work allowances

When: policy extraction. Lowering the generated part allowance to one makes a generated seed refuse, but does not forbid the released fallback. Editable part and bay allowances fit within the fixed released-map ceilings. Coupling both would let a failed tuning experiment invalidate Play recovery.

Gap: generation and saved-map limits previously matched without defining whether they must remain equal. Reach: saved-map support is a release contract, while generation work limits are tunable. Verdict: sound; containment preserves that distinction. Confidence: high.

### Sampled openness remains an assessment, not a physical certificate

When: policy extraction. Raising the median-openness target changes how the sight report judges its samples. It does not change map generation’s mandatory physical coverage proof or block a valid save. Historical tools retain their own sample spacing while sharing the simulation’s calculation.

Gap: the requested validator controls included policies with different meanings. Reach: future reports must distinguish finite samples, map admission and encounter readiness. Verdict: sound; the tool does not claim more than it measures. Confidence: high.

### Source receipts, preset revisions and physical identities have separate jobs

When: publication pass. Exporting a preview preserves all six exact input documents and their content receipts—hashes that identify the exact bytes. A managed preset revision changes when preset contents change; analysis-only edits preserve it. Existing map/config hashes continue to identify physical generation. A seed or revision label alone would lose an unsaved draft’s actual settings.

Gap: drafts needed reproducibility without inventing another map identity. Reach: reports remain attributable after fixtures change, and no-op saves preserve bytes. Verdict: sound; each identity answers one question. Confidence: high.

### One shared owner coordinates fixture publication and capture

When: shared publication extraction and final review. A mechanics save may replace rules before its derived catalog. Both local editors now coordinate byte captures, publication and recovery through one per-checkout queue in the server process. Native validation runs after capture, outside that queue. A mechanics Save response resolves its catalog from the same captured files it returns, so an outside edit after publication cannot mix new files with the earlier catalog. Existing journal names retain their destination checks and outside-edit conflict handling.

Gap: separate editor queues did not protect the workbench’s combined source bundle. Reach: another local fixture editor must use this owner to participate in coherent captures. External hand edits remain subject to stale-source checks. Verdict: sound; readers cannot observe an owned in-process save midway. Confidence: high.

### Reviewed source publication is explicit and held by the server

When: local API pass. Review captures the exact replacements on the server. Save names that candidate and checks all source receipts again; browser-supplied file paths or replacement text do not determine what is written. A stale candidate is rejected without erasing the draft or outside edits.

Gap: the browser needed a trustworthy save boundary. Reach: future save surfaces must publish what was reviewed, not reconstruct it from client fields. Verdict: sound; preview and mutation remain distinct. Confidence: high.

### Displayed geometry is explicitly retained across background work

When: final artifact review. If map A is visible, a superseded successful B followed by refused C must leave A inspectable. Each preview names at most the admitted draft and saved baseline still displayed. The store preserves them plus the current result and latest refusal receipt. Seed samples have separate temporary geometry and attempt export before replacing it.

Gap: “keep the latest success” did not identify the result the browser actually accepted. Reach: artifact lifetime follows displayed identity, not completion order; retention is bounded by the local store’s lifetime. Verdict: sound; stale work cannot evict the visible plan. Confidence: high.

### Rapid edits keep one latest pending draft

When: live editor pass. While A runs, typing B then C leaves only C pending. A cannot become current after C was requested. Manual inspection or sampling first cancels and waits for owned generation; unfinished numeric input suspends regeneration. The alternative is a backlog of obsolete work or concurrent native jobs.

Gap: “live” needed a scheduling contract. Reach: additional foreground actions must use the same cancellation owner. Verdict: sound; work makes bounded forward progress and reports retain their actual input identity. Confidence: high.

### The inspector owns drawing, notes and crop capabilities

When: native visual review. The existing Rust inspector produces the same geometry, palette and formatted notes for standalone output and browser presentation. The browser displays its notes at readable sizes. Features identify their rule group, and only supported settlement/district/bridge features advertise a crop. Selecting district index 3 on map A does not select index 3 on a new map B: selection names both the feature and the retained artifact. Reformatting metrics or guessing crop IDs in JavaScript would duplicate native knowledge.

Gap: interactive navigation needed metadata and readable captions. Reach: future detail views extend the inspector’s capability contract. Verdict: sound; the browser presents native answers without another geometry implementation. Confidence: high.

### Saved input modules refresh on the next page load

When: final lifecycle review. A normal Vite refresh could restart a running battle after a save. The workbench instead invalidates preset/default imports for future loads and suppresses React refresh. The existing developer Restart reloads the page, so it captures fresh inputs; the running page and saved replay keep their captured generation.

Gap: hot publication had to preserve live battles. Reach: new editable gameplay sources need the same capture lifecycle. Verdict: sound; explicit restart and incidental file change have different effects. Confidence: high.

### Invalid numerical drafts are retained report outcomes

When: integrated browser verification. A syntactically valid request with an invalid numerical policy receives an input-stage refusal containing the tested inputs and field diagnostics. Malformed HTTP requests and execution failures remain errors. Treating every domain refusal as an HTTP fault would obscure its usable tuning receipt.

Gap: the local request and domain-result boundaries needed consistent failure semantics. Reach: clients can retain refused drafts without confusing them with transport failure. Verdict: sound; native validity remains authoritative. Confidence: high.

### Seed collision and cancellation preserve exact identities

When: player admission pass. A random seed collision advances within the unsigned 64-bit domain instead of redrawing indefinitely; sample sequences wrap in the same domain. Before admission, Cancel returns only type/size preferences. After admission, labels, links and replay name the actual winner. A placeholder seed never becomes a promised battlefield.

Gap: random collisions and cancellation needed finite identity behavior. Reach: seed text stays exact above JavaScript’s integer range, and exact links remain separate from Play intent. Verdict: sound; every attempted and admitted seed is recorded. Confidence: high.
