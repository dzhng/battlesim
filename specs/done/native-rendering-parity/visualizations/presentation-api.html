The presentation API

Native rendering parity · the presentation API as the user reviewed and approved it on 2026-10-11 (slice 18b). Kept as provenance: the shipped contract, and where it moved since (the 64-byte Instance, no Godot binding, prepare_fog, sound commands), is in the spec's README, and the code is crates/presentation.

The Rust side is as smart as possible; each renderer as dumb as possible. Rust owns everything per entity (unit, joint, chunk, effect, light, eye). Renderers own everything per vertex, texel and pixel, and draw flat records they are handed. Presentation reads only the side's publication and never the simulation's state, so it can't see past fog of war and never moves a digest.

For comparison, the browser uploads about 300 KB a frame today. Most of that is palette staging the GPU kernel then overwrites. Native rewrites a 768 KiB vehicle palette whole each frame with a vehicle in view, and a 1 MB scar table on every change. At 120 fps, Frame's 230 KB is 28 MB/s. The cost to watch is Rust's CPU time on the browser's main thread, which slices 19 and 20 measure.
