# C05: full-extent measuring tools

**Depends on:** C53, C09, C60. **Kind:** slice.

## Question
Does every later resource gate have a pinned tool that measures the selected extents and names its baseline?

## Contract it unlocks
- `city_report` records full-world generation/parse/build/export/load, peak native/wasm/browser memory, navigation build/search/rebuild, eye/fog costs and instructions retired, plus steady-state versus snapshot publication split.
- Pinned type × size startup/layout probes and G0's representative worst-case contact benchmarks use exact request/template identities.
- The contact script includes useful open approaches and street combat; camera tours include ground/tactical/whole-map overview and opposite-edge movement through C57's policy.
- A registered city-scale lab/scene shares these inputs. Reports distinguish whole-world startup/allocation from declared arena-local mechanics measurements.

## API seam
Sim report examples, browser benchmark/preparation owners and lab fixtures, consuming C09's resolved compiled map and identity. No handwritten generator or benchmark-only map format.

## What the human can run or see
Pinned cost/identity tables, city-scale probe and matched contact/camera benchmark. Baseline rows in frame-cost.md/sim-cost.md may miss budget and are labelled as before rows.

## Verification
- Baselines cover all nine type × size startup/layout cases; expensive fights/frame runs cover G0's frozen worst-case representatives, serially.
- Reports include lazy allocations, full snapshots, edge-to-edge access and template residency.
- Requests/scripts/cameras are pinned so before/after numbers compare the same work.

## Delegated to the implementer
Tour waypoints/fight scripts and report presentation within G0's representative-case contract.

## Must stay green
Existing focused benchmark contracts; C56 names its subsequent geometry/cost baseline changes.

## Feedback that would change this slice
